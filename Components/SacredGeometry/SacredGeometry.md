# SacredGeometry

A catalog of **1024 unique, animatable line-art shapes** — sacred-geometry polyhedra, parametric
curves, knots, and fractals — with one pure renderer that targets either a live `<canvas>` or a
static SVG string. No DOM, no RNG, no `Date`: `sample(i, t)` is a pure function of `(index, phase)`,
so the Node-built SVG posters and the browser canvas agree by construction.

Indices **0–83 reproduce Cyberspace's original "schematic" catalog verbatim** (the original 85 shapes
minus the removed harmonograph); the rest are
generated by sweeping parametric families. The catalog was extracted from
`Components/Cyberspace/console-bg.js` so Cyberspace now *feeds* from this component instead of owning
the geometry.

---

## Layout

```
SacredGeometry/
├── sacred-geometry.js   # the catalog + renderer (UMD: browser <script> AND node require())
├── build-previews.mjs   # writes previews/shape-NNNN.svg; doubles as the catalog smoke test
├── package.json         # `npm run build:previews`, `npm run check`
├── previews/            # shape-0000.svg .. shape-1023.svg — static posters (built artifact)
└── index.htm            # QA harness: a live grid of every shape
```

The renderer ships **no CSS** — it draws onto a canvas you own, or returns an SVG string. Each
consumer styles its own surface (Cyberspace keeps its `.cyberspace-geo-*` window chrome; the Legion
gallery styles its `.persona-art` canvas).

## API

```js
SacredGeometry.count                 // === 1024
SacredGeometry.spec(i)               // -> frozen { index, kind, label, posterT }; RangeError if out of 0..1023
SacredGeometry.sample(i, t)          // -> { polylines:[[[x,y]…]…], dots:[[x,y]…] }, normalized to ~[-1,1]; pure
SacredGeometry.draw(ctx, i, t, opts) // strokes shape i at phase t onto a 2D canvas context
SacredGeometry.svg(i, opts)          // -> self-contained <svg> string for one frame
SacredGeometry.label(i)              // -> human-readable name
SacredGeometry.fingerprint(i)        // -> structural hash (used for dedupe / drift detection)
```

**Animation.** A single scalar `t` (phase) drives everything: 3D shapes rotate (`rx = t·0.4, ry = t`),
parametric shapes advance their formula's phase term. Live consumers increment `t` each frame; the
static poster uses the shape's baked `posterT` (a 3/4 view for polyhedra so they're never
axis-aligned; `0` for parametric curves, which is their canonical pose).

**`draw` options** (`opts`): `size` (canvas px box, default 110), `stroke`, `dotColor`, `lineWidth`,
`dotRadius`. Parametric shapes carry their own intrinsic colors; `stroke`/`dotColor` only affect the
wireframe polyhedra. The renderer maps a normalized ~±55 design space into the `size` box centered.

**`svg` options**: `size` (default 110), `t` (default `posterT`), `bg` (background fill; `'none'`
to omit the backing rect).

### Live canvas (Cyberspace / Legion)

```js
function frame() {
  ctx.clearRect(0, 0, c.width, c.height);
  phase += 0.007;
  SacredGeometry.draw(ctx, shapeIndex, phase, { size: c.width });
  requestAnimationFrame(frame);
}
```

## The 1024-shape catalog (band allocation)

| Band | Indices | Family |
|---|---|---|
| 0 | 0–83 | Original Cyberspace catalog (Platonic/Archimedean solids + 22 parametric curves), verbatim minus the harmonograph |
| 1 | 84–124 | Elongated bipyramids |
| 2 | … | n-gonal prisms |
| 3 | … | n-gonal antiprisms |
| 4 | … | n-gonal bipyramids |
| 5 | … | n-gonal pyramids |
| 6 | … | Star prisms {n/k} (coprime) |
| 7 | … | Rose curves r=cos((n/d)θ) (coprime) |
| 8 | … | Lissajous (coprime a:b, three phase offsets) |
| 9 | … | Epicycloids / hypocycloids (lowest-terms R/r) |
| 10 | … | Epitrochoids (R/r, three pen radii) |
| 11 | … | Torus knots (p,q) with depth shading |
| 13 | (5 shapes before band 12) | Koch / Sierpinski fractal depths |
| 12 | … – 1023 | **Gielis superformula** sweep — the elastic tail band that fills exactly up to 1024 |

Exact band sizes float because `add()` rejects any shape whose **geometry** duplicates one already in
the catalog (fingerprint-deduped), so each sweep skips collisions and keeps climbing its parameter
until it finds genuinely new shapes. The superformula band absorbs the slack so the total is always
exactly 1024 — `sacred-geometry.js` throws at load if it isn't.

## Building / verifying the posters

```sh
node build-previews.mjs          # write previews/shape-0000..1023.svg
node build-previews.mjs --check  # validate only (CI / pre-commit): count, no throws,
                                 # non-empty + finite geometry, all 1024 fingerprints unique
```

A non-zero exit means the catalog regressed. Re-run `build:previews` and commit the refreshed
`previews/` whenever `sacred-geometry.js` changes, then bump the CDN tag so consumers pick it up.
